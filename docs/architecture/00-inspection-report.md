### Findings

| # | Finding | Impact |
|---|---------|--------|
| R1 | The repository contains a **Vite + React 18 + TypeScript + Tailwind starter**, generated by a scaffolding tool (`index.html` carries `bolt.new` Open Graph image URLs and the title *"KMS – Enterprise Technology Infrastructure & Security"*). | Unrelated to KMS TV. Its title describes a different product (an enterprise infrastructure/security site, not an OTT platform). |
| R2 | **`src/` does not exist.** `index.html` references `/src/main.tsx`, which is not tracked and not present. | The project in the repository **cannot build**. `npm run build` and `npm run dev` would both fail. It is a non-functional shell, not a working application. |
| R3 | `package.json` declares `@supabase/supabase-js` as a dependency. | Supabase is a hosted Postgres/BaaS product. Its presence implies a data/auth direction that **conflicts** with the stated direction (Laravel 12 + self-managed PostgreSQL + our own auth). See open question OQ-17. |
| R4 | `package.json` is named `vite-react-typescript-starter`, version `0.0.0`, and there is no workspace configuration. | Not a monorepo. No package boundaries, no build orchestration, no CI. |
| R5 | No `.github/` directory, no CI configuration of any kind. | No automated verification exists today. |
| R6 | No `LICENSE`, no `CODEOWNERS`, no `CONTRIBUTING.md`, no issue/PR templates, no `.editorconfig`. | Governance and contribution rules are undefined. |
| R7 | `.gitignore` is a stock Node/Vite ignore file. It ignores `.env` (good) but has no rules for PHP/Composer, Docker, IaC state files, mobile build outputs, or media artifacts. | Real risk of committing `vendor/`, Terraform state, keystores, or large media files once work starts. |
| R8 | No documentation of any kind. | No shared understanding to build on. |

### Decision taken in this phase

The existing starter has been **left untouched**. It is not part of the KMS TV architecture, but
deleting or relocating another party's committed work is not an initialization decision — it is a
product decision. See **OQ-17** in [`ARCHITECTURE.md`](../../ARCHITECTURE.md) for the options and
the recommendation. It must be resolved before Phase 1 line-of-code one, because it determines
whether `/` or `/apps/web` is the home of the web application.

### Environment findings

| # | Finding | Impact / required action |
|---|---|---|
| E1 | **No Docker daemon.** `/var/run/docker.sock` does not exist; `docker info` fails. | Containers cannot be built or run in this session. The `docker compose` development stack defined in Phase 1 must be validated on a developer machine or a CI runner, not here. CI must therefore run on runners that provide a Docker daemon. |
| E2 | **No PostgreSQL server and no Redis server running.** Only client binaries are installed; nothing is listening on any TCP port. | No database-backed work can be executed or verified in this session. Phase 1 must stand these up via the compose stack. |
| E3 | **FFmpeg is not installed.** | No encoding, packaging, or media inspection can be performed or verified here. The media pipeline must be developed against a container image with a pinned FFmpeg build. |
| E4 | **Nginx is not installed**, but is installable from the distribution repositories. | Origin/edge configuration cannot be tested *as shipped*, but can be after installing it. This was done in Phase 3: `infrastructure/nginx/origin.conf` was run against a live `core-api`, and its authorization and cache-key behaviour confirmed. What still cannot be tested here is anything requiring real packaged media. |
| E5 | **PHP `bcmath` is not loaded.** | Several money/decimal libraries and some Laravel first-party packages expect it. The PHP runtime image for KMS TV must enable `bcmath` explicitly, and money must never be handled as a float regardless. |
| E6 | **Network egress is restricted to an allow-list.** Package registries are reachable (`repo.packagist.org` 200, `registry.npmjs.org` 200, `raw.githubusercontent.com` 200). Vendor documentation sites are **blocked** at the proxy (`laravel.com`, `www.php.net` both returned `EGRESS_BLOCKED`). | Dependency **metadata and licences can be verified here** (and were — see [`09-dependency-policy.md`](09-dependency-policy.md)). Vendor **capability claims cannot be verified here** (DRM support matrices, Tizen/webOS platform capabilities, CDN feature sets, PSP APIs). Every such claim in these documents is therefore explicitly marked as *unverified — requires human confirmation against vendor documentation*. This is a hard constraint on how these documents may be used. |
| E7 | No mobile/TV toolchains: no Android SDK, no Gradle, no Xcode (Linux host — Xcode is impossible here), no Tizen Studio, no webOS CLI. | Client application work cannot happen in this environment at all. Phases 8–9 need dedicated build infrastructure, including at least one macOS builder for iOS/tvOS. |

### Consequences for planning

1. This environment is suitable for **backend, web, schema, contract, and documentation work only**.
2. Anything requiring a container runtime, a database server, FFmpeg, or a device toolchain must be
   validated elsewhere. Plans that assume otherwise will silently produce unverifiable work.
3. Because vendor documentation is unreachable, **no third-party capability is treated as known** in
   this initialization. Where a design depends on one, it is written as a port with an explicit
   verification task attached, per
   [`05-integration-boundaries.md`](05-integration-boundaries.md).
